# EXP-D3-05 Final Decision — Authenticated Index 与 GR/RR 状态同步约束设计

## 决策

**B — 保留设计，暂不实现 Halo2 原型。**

理由一句话：GR/RR/IR 的三态语义与同步更新关系可以无歧义定义，16 个负例都能指出应有的拒绝约束；但 **IR↔RR 的一致性在电路中尚无无需全树扫描的证明路径**，且成本模型显示若保留 RR 全扫描则 IR 方案比 E-R1 更贵、若去掉则一致性无法闭合。在脑中"设计完成"不等于"可以落地为更优电路"。

## 为什么不是 A（进入原型）

- Phase 3 §5 明确指出"IR 能否替代 RR 全扫描"是核心阻断，当前没有无需扫描的证明路径；此时写电路要么保留 RR 扫描（比 E-R1 贵），要么引入未证明的一致性假设（放宽语义）
- 16 个负例中 N05/N06（Parent 撤销有效性）、N09–N11（三支路同步）的拒绝约束都依赖尚未设计的跨结构关系；实现会重复"语义未闭合就堆工程"的风险
- 成本模型无任何实测支撑，违反"不得以理论哈希数量下降直接宣称性能提升"

## 为什么不是 C（放弃 IR 保留 E-R1）

- 三态索引语义自洽，与 D 参考模型对齐（REVOKED 不可再 Grant）；host 密码学结构（D3-04-R1 的 16 测试）已验证可认证、可更新、非法转换根不变
- 接口 B 的承诺哈希不增加 permutation，8 instance 兼容路径存在
- 没有发现"无法合理解决的认证缺口"——阻断是需要更多设计工作，不是逻辑上不可能；成本收益是"不明确"，不是"明确不合理"

## 冻结范围确认

- 本阶段未修改：A/B/C/D/E、E-R1、E-R2、R3、D3-04、D3-04-R1 的任何实现/测试/文档
- 本阶段产出：7 份设计文档，无 Halo2 电路、无新增测试、无模型实现改动
- 8 个 public instances、最多 2 事件、K=15/16 槽/深度 4 的冻结值未被触碰

## 建议的后续（不在本阶段执行）

1. 先设计 `IR(parent)=ACTIVE ⇒ parent∉RR` 的可证明关系（这是能否降成本的关键，可能需状态承诺里加 RR 摘要或辅助索引）
2. 在 host 层补 S0 孤立 RR 检查与 IR↔GR/RR 一致性检查，明确为可信锚定的一部分
3. 只有当上述关系设计闭合、且成本模型显示净置换数低于 344 时，才进入最小 Halo2 gadget 原型，并与 E-R1 同轮 benchmark
4. E-R1 继续作为语义基线保留；本阶段不削弱、不替换它

## 最终结论

IR 可以成为一个**语义清晰、有明确信任边界**的认证索引设计，但在"不牺牲授权语义"与"证明成本合理"两个条件上，后者尚未被验证。按任务包三选一标准，落入 **B：保留设计，暂不实现**。
