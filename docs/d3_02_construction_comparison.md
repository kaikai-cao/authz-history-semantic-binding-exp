# EXP-D3-02-02 — 三种证明构造的完整比较

**基线**：`dc13e810`（D3-01-R1）
**范围**：只做设计与约束规模估算；本轮不写 Halo2 电路，不产生真实证明时间。

---

## 0. 结论先行

**推荐第一版：方案 A（固定容量的完整事件批次重放），深度 4、最多 2 个 grant + 1 个 revoke、DirectOnly。**

不是因为 A 最"创新"，而是因为：

1. 只有 A 能把 D3-01 已经钉牢的**全部语义规则**逐条搬进电路并用负向测试验证；
2. B（状态差分）在数学上无法自己给出"没有隐藏应当发生的撤销"——它必须借用 A 的批次重放或外部完整性假设，否则只是"差分合法"而非"历史正确"；
3. C（递归/分批）在当前规模下解决的是证明工程问题（内存、可增量），而不是本轮的核心研究问题（到底哪些语义需要证明）；本仓没有任何递归 verifier 实现，不能声称它已可用。

**本设计相对 D3-01 真正增加的密码学保证**：证明者在不知道验证者私有信息的前提下，**不能**对"违反授权规则的批次"生成可通过验证的证明；且该证明把前状态锚 `C_prev`、批次承诺 `D_E` 与结果根绑定为同一个语句。D3-01 的链下重执行给出的是"发现错误"，Halo2 证明给出的是"错误批次根本无法产生接受证明"。它**不**增加历史完整性和新鲜性保证。

## 1. 成本计量口径（可复核）

所有数字来自**本地已安装源码的静态推导**，不是实测证明时间。

### 1.1 Poseidon 参数（一手源码）

- `halo2_poseidon 0.2.0 / src/p128pow5t3.rs`：`P128Pow5T3` 为 width 3、rate 2，
  `R_F = 8`、`R_P = 56`，S-box `x^5`。
- `halo2_gadgets 0.6.0 / src/poseidon/pow5.rs`：`Pow5Chip` 每个全轮占 1 行、
  两个半轮合并为 1 行，因此
  - **每次 permutation = 4 + 28 + 4 = 36 行**；
  - 全轮门 WIDTH=3 条约束 × 8 行 = 24；半轮门 (2 + (WIDTH-1)) = 4 条 × 28 行 = 112；
    合计 **136 条约束/置换**；
  - 每个 absorb 块额外 1 行 `pad-and-add`，RATE+1 = 3 条约束。
- `ConstantLength<L>` 的块数 `k = ceil(L / 2)`；一次 `Hash` 调用执行 `k` 次置换、`
  k` 行 absorb。因此：

| 调用 | L（含域标签） | k | 行数 | 约束数 |
| --- | --- | --- | --- | --- |
| `node_hash = Poseidon(D_NODE, left, right)` | 3 | 2 | 72 | 2×136 + 2×3 = **278** |
| `revoke_leaf = Poseidon(D_REVOKE, id, revoker, epoch)` | 4 | 2 | 72 | **278** |
| 事件承诺（grant，含 type 与 7 字段） | 9 | 5 | 180 | 5×136 + 5×3 = **695** |
| `grant_leaf`（D3-01 原样，9 词） | 9 | 5 | 180 | **695** |
| `state_commitment = Poseidon(D_STATE, GR, RR, epoch, policy)` | 5 | 3 | 108 | 3×136 + 3×3 = **417** |

这些是可复核的上限估算：实际布局可能因 lift/copy 与复用而略有变化；行数与约束数都不等于
证明时间。

### 1.2 其他门（估算区间，需实测确认）

| 检查 | 实现思路 | 约束量级 |
| --- | --- | --- |
| scope 子集 `child & ~parent == 0` | u64 拆 8 字节 + 逐字节位运算 | 10–30 |
| resource 前 8 字节相等 | 8 字节查找表 + 相等约束 | 15–40 |
| epoch u64 单调 | 8 字节分解 + 比较链 | 20–60 |
| issuer == parent.subject | 域元素相等 | 1（但父叶子打开另算，见下） |
| 布尔标志（valid / event type / 撤销标记） | selector 或 boolean gate | 1–3 每项 |

规则检查合计按 **80–150 条/事件**计。

### 1.3 基准参照（不是本设计的实测）

D2-A（冻结）在本机 `k = 12`、固定两条深度 4 路径下实测约 **2.1 s 证明 / 47 ms 验证**、
proof 5824 字节（见其 `results/experiment_report.md` §6）。本报告所有时间外推都以它为
"同量级参照"，不写成 D3-02 的实测值。

## 2. 方案 A — 完整事件批次重放证明

### 2.1 完整方案

**公共输入**：见 `d3_02_public_statement.md` §2 的 8 字段语句。

**私有 witness**：

- `GR_prev, RR_prev`（前状态双根）；
- `E = (e_1, ..., e_n)`，每个事件全部字段；
- 每个事件处理后的中间根 `GR_i, RR_i`；
- 每个事件涉及叶子的 Poseidon preimage 与深度 `d` 的兄弟路径；
- 子授权事件的 parent 叶子 preimage 与其在**当前** GR 中的路径。

**约束步骤**（对每个 `i = 1..n` 顺序执行）：

1. **事件格式**：类型标签 ∈ {0x01, 0x02}，域标签固定；计算 `c_i = Poseidon(D_EVENT, ...)`。
2. **语义**（Grant）：
   - `epoch_i >= last_epoch`（u64 比较）；
   - `grant_id_i` 不在当前 GR 中（用 nullifier/槽位承诺的非成员证明或槽位占用标记）；
   - parent 为空 → 根授权；否则打开 parent 叶子，检查存在、`valid=1`、
     `issuer == parent.subject`、`epoch_i >= parent.epoch`、
     `scope_i & ~scope_parent == 0`、resource 前 8 字节前缀匹配。
3. **语义**（Revoke）：打开目标 GR 叶子取 `issuer` 与 `valid`，检查存在、`valid=1`、
     `revoker == issuer`、目标未在 RR 中。
4. **策略**：`policy_id` 为硬编码常量；`DirectOnly` 只改目标，`Cascade` 另起一套电路，
   后代集合由私有 witness 给出，并用 parent 链逐条约束其传递性（第一版只做 DirectOnly）。
5. **GR/RR 更新**：重算受影响叶子承诺，按深度 `d` 逐层 `node_hash` 更新，得到 `GR_i, RR_i`。
6. **批次绑定**：`D_E == Poseidon(D_BATCH, n, c_1..c_n)`。
7. **终止**：`GR_n == GR_next`、`RR_n == RR_next`、`epoch_n == epoch_next`、
   `epoch_prev <= epoch_next`。

### 2.2 每个事件的约束与路径长度

深度 `d` 时，每棵树更新一条叶子的路径需要 `d` 次 `node_hash`；打开 parent 叶子再需要 `d` 次。
以 `d = 4`（最小原型）计：

| 项 | 行数 | 约束数 |
| --- | --- | --- |
| 事件承诺（grant L=9） | 180 | 695 |
| grant 叶子承诺 L=9 | 180 | 695 |
| GR 路径更新 4 × node_hash | 288 | 1112 |
| parent 叶子打开 + 路径（最坏，不复用） | 252 | 1807 |
| 规则检查 | — | 80–150 |
| **单个 grant 事件小计** | **≈ 900** | **≈ 4 400–4 500** |
| 事件承诺（revoke L=5）+ revoke 叶子 | 108 + 72 | 417 + 278 |
| RR 路径 + GR valid 翻转路径 | 576 | 2224 |
| 规则检查 | — | 80–150 |
| **单个 revoke 事件小计** | **≈ 756** | **≈ 3 000–3 100** |

加上前状态承诺开承诺（417）、批次承诺聚合（≈417）与终止检查，2 grant + 1 revoke 的原型
预计 **约 1 300–2 000 行、7 000–9 000 条约束**。相对 D2-A 的 k=12 电路约大 1.5–2 倍。

深度从 4 增至 12 时，每条路径多 8 个 `node_hash`（8×278 = 2 224 约束），单事件成本约
翻倍到 **6 000–12 000 约束**。这与 D3-01 参考实现中深度 12 初始化哈希占主导的观察一致
（但那是 Rust 计时，不是电路约束）。

### 2.3 证明时间趋势与最大批次容量

- **证明生成**：行数近似线性于 `n × d`，ATS/MSM 成本随行数增长；单片大电路没有递归时
  内存峰值也随行数线性增长。以 D2-A 的 ~2.1 s / k=12 为参照，原型（约 1.5–2 倍行数）
  粗估 3–6 s/证明；**未实测，不作为结论**。
- **验证**：IPA 验证主要是对许诺的 MSM，随 `k` 对数增长但常数不小；D2-A 的 47 ms 是
  k=12 下的一条参考线。
- **最大批次容量**（仅按 2^k 行数预算，忽略内存/时间）：

| 电路 k | 域大小（行） | 深度 4 可容纳事件数（估） | 深度 12 可容纳事件数（估） |
| --- | --- | --- | --- |
| 12 | 4 096 | 3–4 | 1–2 |
| 16 | 65 536 | 60–70 | 20–30 |
| 20 | 1 048 576 | 900–1 100 | 300–400 |

**注意**：`k` 是域大小不是实际约束行数（D2-A 报告已强调）。上表是设计预算，
超过后必须用 B 或 C 分片。

### 2.4 威胁边界

- **能证明**：给定可信 `C_prev` 与 `D_E`，`E` 的每一条事件都满足 D3-01 规则，
  且双根确实由 `E` 更新得到。
- **不能证明**：`E` 是授权服务完整历史的连续片段；`C_prev` 是"当前"状态；
  证明生成后没有新撤销；DENY。
- **典型攻击**：证明者删掉一条 revoke 事件，只要他同时让可信批次来源对删减后的 `D_E`
  签名，电路仍接受。防御在外部日志（见 `d3_02_security_analysis.md` §1）。

## 3. 方案 B — 状态差分证明

### 3.1 完整方案

不再逐事件重放，而是把状态变化表示为差分集合：

```
Δ = { (slot, id, old_leaf, new_leaf, tag, sibling_path_old, sibling_path_new) }
tag ∈ {UNCHANGED, INSERT, DELETE, UPDATE}
```

公共输入仍用 §2 的 8 字段语句；`D_E` 必须覆盖 Δ 中每个变更对应的事件承诺。

**约束步骤**：

1. 对每个变更槽位，打开旧树叶子 `old_leaf` 与新树叶子 `new_leaf` 到 `GR_prev` / `GR_next`
   （或 RR 双树各自一条路径）。
2. `tag` 与 `(old_value, new_value)` 的一致性：
   - `INSERT`: old = 空叶子(0) ∧ new = `grant_leaf(e)`；
   - `DELETE`: new = 空叶子(0)（本实验不删除历史记录，仅逻辑删除，故实际不用）；
   - `UPDATE`: old 与 new 的 id 相同、preimage 中仅 `valid` 从 1 变 0；
   - `UNCHANGED`: old == new。
3. 合法性证明：对 `INSERT`，把事件 `e` 的字段拆出，打开其父叶子并用与 A 相同的
   scope/issuer/resource/epoch 规则；对 `UPDATE`（撤销），打开旧 GR 叶子取 issuer，
   检查 `revoker == issuer` 且 RR 叶子为 `revoke_leaf(e)`。
4. **未修改区域不变**：对每个 `UNCHANGED` 槽位约束 old == new；更重要的是，必须证明
   **所有**变更槽位都被列出。Merkle 路径只能证明被打开的叶子，无法证明未打开的叶子
   没变。可行的补强是：
   - (a) 打开全部 `2^d` 个叶子（退化为 A 的全量重算，且证明规模更大）；
   - (b) 改用多项式/向量承诺（Verkle 类），一次打开证明整个求值一致性——本仓没有该原语；
   - (c) 承认这是外部假设：由可信状态服务证明"Δ 是完整差分"，电路只证明"Δ 内部合法"。

### 3.2 关键研究结论：差分合法 ≠ 历史完整

必须把两件事分开：

- **差分合法**：`GR_next` 与 `GR_prev` 的差异可以表示为一组规则合法的叶子更新。
- **事件批次完整**：这些更新确实对应了授权服务真实发生且未遗漏的事件。

Merkle 多点更新证明只给前者。即使每个变更叶子都有合法事件背书，证明者仍可：
1. 从批次中删掉一条 revoke 事件（不把它放进 Δ），得到一个"更宽松但仍合法"的 `GR_next`；
2. 跳过高 epoch 的事件，只提交低 epoch 的差分；
3. 用一个合法的旧状态作为 `GR_prev`（若 `C_prev` 不锁定 epoch）。

唯一的桥接是把 `D_E` 定义为 **Δ 中所有事件的 Poseidon 承诺**，并让验证者从可信来源取得
`D_E`。这样"隐藏撤销"会改变承诺而被拒绝。**这实际上把 B 退化成"带差分优化的 A"**：
语义仍依赖事件背书，完整性仍依赖外部承诺。

### 3.3 约束规模

以 `m` 个变更叶子、深度 `d` 计：

| 项 | 行数 | 约束数 |
| --- | --- | --- |
| 每变更叶子两条路径（旧+新）`2m·d × node_hash` | `2m·d × 72` | `2m·d × 278` |
| 每变更叶子事件承诺 + 合法性规则 | 与 A 的对应事件相同 | 与 A 相同 |
| `UNCHANGED` 槽位（若打开 `2^d - m` 个） | `(2^d - m) × 72` | `(2^d - m) × 278` |

- `d=4, m=2`：路径 16×278 = 4 448 约束，加事件与规则与 A 同量级（约 5 000–7 000）。
- `d=4, m=4` 且打开全部 16 个叶子：16×278 = 4 448（路径）+ 12 个 unchanged 检查，
  成本反超 A。
- 优势只在 `m << 2^d` 且**允许 (c) 外部完整性假设**时出现；本轮的核心问题恰恰是不敢轻易
  接受这个假设。

### 3.4 适用条件

适合"状态服务可信地发布完整差分"的场景（例如服务本身是透明日志且有审计者逐条验证）。
在本研究的威胁模型（状态服务可被攻破）下，B 单独使用不安全。

## 4. 方案 C — 递归 / 分批状态转换证明

### 4.1 完整方案

把长历史切成批次 `B_1..B_t`，每个批次一个证明：

```
π_i : (C_{i-1}, D_{E_i}, n_i, policy_id, epoch_{i-1}, epoch_i) → C_i
```

递归聚合：

```
π* : (C_0, A_t, epoch_0, epoch_t) → C_t
其中 A_i = H_acc(A_{i-1}, D_{E_i}, C_i) 为批次累积器
```

每个递归步的电路同时：
1. 执行本批次的规则检查（同 A，但规模固定，参数统一）；
2. 验证前一步证明的累积状态（Halo 的 accumulation / deferred checks，见
   `d3_02_related_work.md`）；
3. 把 `(C_{i-1}, C_i, D_{E_i})` 绑定到公开累积器 `A_i`。

### 4.2 Halo2 递归可行性（诚实边界）

- **理论/协议层**：Bowe/Grigg/Hopwood 的 Halo（ePrint 2019/1021）实现了无 trusted setup
  的递归组合，用普通椭圆曲线 cycle 上的离散 log 假设与 IPA 累积；halo2 book 的
  `background/recursion` 章节也描述了 accumulation 与 deferred checks。
- **本仓工程层**：`halo2_proofs 0.4` 使用 Pasta（Pallas/Vesta）cycle，D2-A 已用
  Pallas base field + Vesta 承诺实际生成/验证 proof。这提供了递归所需的曲线条件。
- **但是**：本仓**没有** in-circuit verifier / accumulation gadget 的实现或测试；本轮也没有
  实现它。因此"C 在本场景可用"目前只是**可行性判断**，不是已验证事实。任何成本数字都
  不能写成实测。
- **统一电路参数**：递归要求每步电路 shape 完全一致（同样的 `k`、同样的列布局、
  同样的 selector 集合）。因此各批次的事件数与策略必须固定上限；变长批次要 padding。
- **中间根绑定**：`C_i` 必须同时出现在 π_i 的 public output 和 π_{i+1} 的 public input；
  否则出现"断链"。
- **防止跳过某一批次**：
  - 验证者从可信 checkpoint 取得**最终** `C_t` 与 epoch，跳过批次只会得到较早的 `C_j`，
    与 checkpoint 不等 → 拒绝；
  - 或公开累积器 `A_t`，由可信日志提供期望值。仅凭"递归证明有效"无法防跳过——
    一条较短的合法链同样能通过验证。
- **递归验证成本 vs 单个大电路**：
  - 优势：prover 内存峰值固定、可并行逐批生成、最终 proof 尺寸不随批次数增长；
  - 代价：每步要在电路内做 IPA accumulation 与曲线运算，单步电路显著大于小批次 A；
    需要 cycle，不能任意换曲线；实现与审计复杂度高。
  - 对 `n ≤ 2` 的原型，递归开销远大于收益。

### 4.3 约束规模估算

本轮只给出**结构性结论**，不给精确数字：

- 单步 = A 的固定批次电路（深度 4、m=2，约 7 000–9 000 约束）+ 递归 verifier 开销；
- 递归 verifier 开销依赖具体实现与是否使用 accumulation，本仓无代码，记为 **UNKNOWN**；
- 总约束 ≈ `t × (单步 A + 递归开销)`，内存峰值不再随 `t` 增长。

把它写成"递归一定更便宜"是不诚实的；只有在 `t` 很大或需要增量更新时才可能划算。

## 5. 三方案完整对照

| 维度 | A 完整重放 | B 状态差分 | C 递归分批 |
| --- | --- | --- | --- |
| 电路输入 | 全部事件 witness | 差分叶子 + 事件背书 | 每批事件 + 前序证明累积器 |
| 语义规则覆盖 | 全部，逐事件 | 需逐变更背书；未列变更无约束 | 每批同 A |
| 历史完整性 | 依赖外部 `D_E` | 依赖外部 `D_E`，且更弱 | 依赖外部 `D_E` + 最终 checkpoint |
| 前状态锚定 | `C_prev` | `C_prev` | `C_0` + 每步 `C_i` 链 |
| 窥私 | 事件全私有；根公开 | 变更叶子值进入 witness；未变更叶子不打开 | 同 A，但中间 `C_i` 公开 |
| 深度 4 / 2 事件约束量 | ~7k–9k | ~5k–7k（但完整性弱） | ~单批 A + UNKNOWN 递归开销 |
| 随 n 增长 | 线性 | 随变更数 m 线性 | 单步固定，总量线性、内存固定 |
| 最大批次（k=12 估） | 3–4 事件 | 视 m 而定 | 受单批上限约束 |
| 证明时间趋势 | 随行数线性增 | 同左 | 单批固定；总生成时间 t 倍 |
| 主要风险 | 大批次不可行 | 隐藏变更 / 隐藏撤销 | 递归实现未验证；跳批次 |
| 适用条件 | 小批次、语义证明优先 | 可信服务发布完整差分 | 长历史、需要增量与固定内存 |

## 6. 推荐与不推荐理由

**第一版选 A**。它不是为了"把历史放进 Halo2"而做电路，而是把 D3-01 已经可证伪的
11 条规则逐一变成"无接受证明"的约束。它回答了真正值得证明的关系：
`T(S_prev, E) → S_next` 的**语义正确性**。

**不选 B 作为第一版**：它把"未修改区域不变"和"没有隐藏撤销"留给了外部假设或更强的
承诺原语。在状态服务可被攻破的威胁模型下，这等于把本轮最想证明的东西又交还给了链下。
它可作为 A 之后的优化方向（先有语义证明，再谈差分压缩）。

**不选 C 作为第一版**：本原型最多 2 事件，递归开销远大于收益；且本仓没有递归 verifier，
用 C 会引入一个无法实现的核心依赖。但**不能因此断言递归没有空间**：现有工作
（Halo、Nova、Reckle/Verdict）没有覆盖"多授权来源 + 部分撤销 + 隐藏授权历史 +
外部最新状态绑定"的组合，这正是后续可研究点。
